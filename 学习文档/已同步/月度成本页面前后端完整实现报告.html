月度成本页面前后端完整实现报告

"月度入库成本"不是孤立的 Vue 页面，而是一条跨 3 个工程、4 类存储/数据源和 1 个调度平台的业务链。本文以当前磁盘代码为准，说明页面、接口、计算链路、数据模型和运行环境，使开发人员能按文重建。

证据原则：本文以当前磁盘代码为准。代码不能证明的网关、Nacos、数据库连接、XXL-JOB 管理端配置等均明确标注为"环境待确认"。文中不记录仓库里出现的明文密钥。

本文覆盖当前实现中的查询与筛选、动态厂区列、前端草稿、整体/单厂编辑、批量保存、整月提交、定时计算、日成本三源合并、BI 加权、鲜价校验、Mongo 双集合、下拉接口、临时重算与日明细接口、构建部署和测试现状。

不把设计文档中尚未落地的方案当作现状：计算就绪元数据 calcReady/dataReady/editable/notReadyReason、真正的导出、定制品批量查询均未在当前代码中实现。

3.3 表格列和响应透视

固定列：批次月份、二/三/四级分类、产品状态、规格编码、规格名称、冻品属性；随后追加当前选择的厂区列和操作列。后端返回 factories[]，前端 transformRows() 转换为 row['103'] = 12.34 与 row._factoryMap['103'] = 完整厂区对象。动态厂区单元格从 row[factoryCode] 显示成本，从 _factoryMap 读取初算成本、鲜价、原因和厂区存在性。显示格式为一位小数；后端持久化仍是两位小数。

tableKey 由所有列 prop 拼接，厂区选择变化时强制重建表格并调用 doLayout()。免冻品厂区列使用浅蓝背景。产品状态映射：1=产品正常全流程可用、2=允许报单，不允许生产、3=全部禁用。

3.5 权限与时间状态

角色判断仅为 userInfo.role_name.includes('冻品运营负责人')，该角色才显示保存、提交、手动计算和编辑入口。页面文案声称"每月 2 日 07:00 之后可操作上月"，实际实现是 day === 2 && hour >= 7——实际窗口只有每月 2 日 07:00 至 23:59，3 日起又关闭。判断使用浏览器本地时区，不是 Asia/Shanghai。

2 日 07:00 前且查看上月时，页面不请求列表，显示"正在计算中"。它只按时间推测就绪状态，没有读取 Job 实际成功/失败状态。路由守卫只处理 token、锁屏和通用 meta.isAuth；静态 URL 和前端按钮隐藏不是后端授权。

3.6 编辑弹窗与强校验

编辑分两种模式：厂区编辑（点击厂区成本，携带 factoryCode）与整体编辑（点击"整体编辑"，不携带 factoryCode，后端把同一成本写入全部厂区）。进入编辑前依次检查：负责人、时间窗口、上月、未提交（dataStatus === 2 已提交）、免冻品、目标厂区存在。整体初算展示采用所有厂区 originalCost 的最高值，但真正校验会遍历根层和每个厂区。

输入先删除所有非数字和小数点字符，再限制两位小数。注意：粘贴 -10 会被清洗成 10，这是当前行为。最终正则要求 ^\d+(\.\d{1,2})?$。

前后端一致的强规则：仅免冻品可编辑；已提交不可编辑；修改原因必填；成本非负、后端 HALF_UP 保留两位；修改成本不得低于系统初算成本；当鲜品价高于月度成本时，差额不得超过五档阈值。

月度成本区间（元/kg）鲜价最多高出（元/kg）
< 100.5

鲜价为空，或鲜价不高于修改后成本时跳过价差校验。

3.7 前端草稿与批量保存

弹窗"确认"不调用接口，只写入内存 pendingEdits。草稿键：整体 batchMonth|specCode|R；厂区 batchMonth|specCode|F|factoryCode。每项保存 mode/batchMonth/specCode/factoryCode/factoryName/monthlyCost/editReason/originalCost/confirmedAt。

同一规格同时存在整体和厂区草稿时使用 LWW（Last Write Wins）：比较 confirmedAt，时间更晚者决定该厂区的页面展示。保存队列算法：按 batchMonth|specCode 分组；有整体草稿时先调用整体 /edit；不晚于整体草稿的厂区草稿被整体覆盖，整体成功后一起清除；晚于整体草稿的厂区草稿按确认时间升序继续调用；没有整体草稿时，厂区草稿按确认时间升序保存。saveData() 串行执行队列，成功项从草稿删除并重新查询，失败项保留，允许"部分成功"。没有服务端批量保存接口。

草稿在同月查询/翻页后通过 mergePendingIntoRows() 回显。切月、重置、浏览器关闭和子组件 beforeRouteLeave 有丢弃提示；但父 tab 的 handleBeforeLeave() 只保护 fixed/coeff，从 monthly tab 切到同页其他 tab 时 monthly 子组件可能被 v-if 销毁而没有可靠提示。

3.8 提交与 Axios 请求层

提交前要求负责人、可编辑窗口且没有前端草稿，确认后请求 POST /frozen/monthly-cost/submit，body 为 {"batchMonth":"2026-06"}。提交是整月操作，不是当前页或当前筛选结果。API 封装统一前缀 /api/muyuan-slaughter-opms-frozen-cost-accounting；Axios 拦截器负责访客标识、应用编码、Basic Authorization、Bearer token、60 秒默认超时、NProgress、业务码/HTTP 错误提示。手动计算单独把超时设为 15 分钟。由于响应拦截器通常已对非 2xx 业务码 reject，组件里部分 res.data.code !== 200 分支可能不会执行，catch 中又会再次提示，存在重复消息风险。

5. 成本服务实现

5.1 分层与调用关系

FrozenMonthlyCostController
  -> FrozenMonthlyCostServiceImpl
       -> MonthlyCostValidator
       -> MyMonthlyCostSavedRepository / MongoTemplate
       -> MyMonthlyCostSubmittedRepository

FrozenMonthlyCostCalcJob / 临时 calc Controller
  -> FrozenMonthlyCostCalcHandler
       -> 定值 submitted Mongo
       -> 系数 submitted Mongo
       -> MDM Feign：ZCO116D / BI / 鲜价
       -> 产品主数据 Mapper
       -> 月度 saved Repository

5.2 状态机

重算规则：新规格插入；已有状态 0 可覆盖；状态 1/2 跳过，避免覆盖人工修改或已提交数据。状态 2 禁止编辑并被提交锁定。

5.3 单厂编辑

核心步骤：检查规格、月份、成本必填 → 按 specCode + batchMonth + isDeleted=0 查 saved → 检查未提交、免冻品 → 原因 trim 后必填、成本 HALF_UP 两位 → 找目标厂区 → 校验不低于厂区 originalCost → 校验厂区鲜价五档 → 内存替换目标厂区，重算根层成本/重量/鲜价 → 原子更新目标数组元素及根层字段，状态改为 1。

Repository 条件：规格、月份、未删除、状态不为 2、厂区存在。单厂更新没有 expectedUpdateTime 条件。

5.4 整体编辑与根层汇总

不传 factoryCode 时：把相同成本和原因写入每个厂区；对每个厂区执行初算下限和鲜价五档校验；重算根层；用 updateTime == expectedUpdateTime 作为乐观锁，整体替换 factories；状态变为 1。厂区聚合到根层：有正 monthlyInWeight 时按厂区月入库量加权；所有厂区无正重量时对非空厂区值做算术平均；金额保留两位 HALF_UP；根层 originalCost 是系统初算快照，人工编辑不覆盖。

5.5 整月提交与事务

@Transactional(rollbackFor=Exception.class)：按月份查全部有效 saved → 拒绝空月、已提交、非法状态、无厂区数据 → 根层和每个厂区复验成本非空、初算非空、不得低于初算 → 不复验鲜价差（系统初算可能天然超阈）→ submitted 若该月已有快照则拒绝 → 每条 saved 转为 submitted 快照并插入 → 批量把该月 saved 的状态 0/1 更新为 2 → 实际锁定数不等于预期数则抛异常，使整月回滚。

Mongo 事务管理器在 *-start 配置类注册。MongoDB 必须是副本集或支持事务的分片集群；standalone Mongo 无法提供该事务语义。

5.6 服务端授权现状

Service 注释明确写着角色、2 日 07:00 和仅上月均由前端负责；MonthlyCostValidator.assertEditableDay/assertPreviousMonth 已废弃且为空操作。Controller/Service 当前没有月度业务角色和时间窗强校验。能通过平台基础认证直接调用接口的主体可绕过页面按钮调用 /edit、/submit、/calc 和 /dailyCostDetail。这是当前实现事实，不应在复现时误认为前端权限已形成安全边界。

6. 月度自动计算

6.1 调度入口

Handler 名 frozenMonthlyCostCalcJob；注释 Cron 0 0 7 2 * ?；业务时区 Asia/Shanghai；默认计算上月；XXL-JOB 参数非空时覆盖月份，可用于历史重跑；异常返回 ReturnT.FAIL。Cron 只存在于代码注释，真正调度必须在 XXL-JOB 管理端配置（环境待确认）。

6.2 日成本来源与优先级

来源数据来源标记
定值成本 submittedfixedCostFIXED
系数成本 submittedcostCOEFFICIENT
MDM ZCO116DinWahseCostCUSTOM

定制品接口按自然月逐日调用 28 至 31 次，只接纳规格编码以 2 或 4 开头的记录。根目录《定制品日度成本批量查询改造方案》尚未落地。

6.3 厂区月成本公式

起始日 = 本月首个存在有效日成本的日期
扫描区间 = 起始日 .. 月末

若存在"日成本非空 且 日入库量 > 0"的日期：
  月成本 = Σ(日成本 × 日正入库量) / Σ(日正入库量)
  monthlyInWeight = 实际参与公式的正入库量之和

若没有任何正权重日期，但存在有效日成本：
  月成本 = 有效日成本的算术平均
  monthlyInWeight = 0

结果 = HALF_UP 保留 2 位

若某日有正入库量但缺日成本，该日重量被排除并写 missingDailyCostWarning。首个成本日之前的重量完全不扫描。因此文档中的 monthlyInWeight 不是 BI 全月净入库总量，而是成功参与计算的正重量。

6.4 根层公式与产品主数据

根层月成本 = Σ(厂区月成本 × 厂区参与重量) / Σ(厂区参与重量)
根层鲜价   = Σ(厂区鲜价 × 厂区参与重量) / Σ(厂区参与重量)
若全厂区无正重量，则分别对非空厂区月成本、鲜价做算术平均。
根层 originalCost 保存系统初算结果；monthlyCost 初始等于它。

成本服务从 MySQL 产品主数据补充名称、二/三/四级分类和状态。规格要求产品启用、分类有效且 one_class_code='11'。冻品属性映射：frozen_property == 1 → 免冻品；其余值和缺失 → 非免冻品。只有免冻品允许人工编辑。

7. MDM 三类数据接口

7.1 BI 日入库重量

调用链：成本 Feign POST /api/frozen/bi-inbound-weight/query → BiInboundWeightController → Service → @DS(MYRS_BIGDATA) Mapper → Hologres。请求 {batchMonth, startDate, endDate}；Service 手工校验非空、严格日期格式、起止顺序，并要求范围完整覆盖 batchMonth 的自然月。响应项 inboundDate, specCode, factoryCode, netWeightKg（kg）。数据表 rs_ads.ads_yy_bi_sale_froze_rcpt_detail_di，粒度日期 + 产品 + 厂区，查询范围 [startDate, endDate + 1 day)。

当前聚合是 MAX(sum_out_in_wahse_wgt) AS netWeightKg，不是 SUM。这一口径假设源字段是重复快照而非可累加明细。SQL 不过滤零/负值；计算消费者只使用 > 0 的重量。BI 调用异常、失败响应、空必填字段会使整月计算失败。

7.2 鲜品自然月均价

调用链：POST /api/frozen/fresh-monthly-price/query，请求 {"batchMonth":"2026-06"}，响应 batchMonth, comCode, prodCode, monthlyAvgPrice（元/kg）。数据表 rs_ads.ads_hs_api_gas_prc_di，范围 [月初, 下月月初)。公式：SUM(inv_pre * factory_product_weight) / NULLIF(SUM(factory_product_weight), 0)；SQL 过滤价格非空、重量非空且大于 0、厂区/产品编码非空。鲜价调用失败不会阻断月成本计算，而是降级为空映射；结果仍可落库，但后续编辑会因鲜价为空而跳过价差规则。

7.3 SAP ZCO116D 定制品日成本

该接口不直接调用 SAP，而是查询已同步到 Hologres 的表：POST /api/frozen/sap-zco116d/query?batchDate=...&specCode=可选。响应 dt, prodCode, prodName, comShortName, inWahseCost。数据表 rs_ads.ads_hs_api_froze_pos_co116d_df，有效期条件 lock_start_date <= batchDate AND lock_end_date >= batchDate；可选规格条件是 prod_code LIKE '%specCode%'。SQL 无聚合、无去重；若有效期重叠导致同源重复，消费者会判整月失败。comShortName 在成本服务通过精确名称映射到十厂编码，不 trim、无别名；无法映射即整月失败。BI factoryCode 和鲜价 comCode 则被直接假定已经是同一标准编码域。

7.4 MDM 数据源

三个 Mapper 都通过 @DS(MyDataSourceConstant.MYRS_BIGDATA) 使用常量值 myrs_bigdata_dev。生产也必须注册该逻辑数据源键，或在部署前修改命名（环境待确认）；需要在 Nacos/启动配置提供 JDBC URL、驱动、账号、密码、连接池参数，并授予三个 rs_ads 表 SELECT 权限。

8. MongoDB 数据模型

8.1 saved 集合

集合 my_frozen_monthly_cost_saved。根字段：_id（Long 雪花 ID）、specCode/specName/batchMonth、二/三/四级分类、productStatus/frozenAttribute、monthlyCost/originalCost/monthlyInWeight/freshMonthlyAvgPrice、editReason/dataStatus、factories[]、submitUser/submitTime、createTime/updateTime/createUser/updateUser/isDeleted。

厂区字段：factoryCode/factoryName、四个金额字段、editReason、dailyCosts[]、sourceConflictWarning/sourceConflictSummary、missingDailyCostWarning/missingDailyCostSummary、updateUser/updateTime。日字段：date, dailyCost, dailyInWeight, sourceType(FIXED/COEFFICIENT/CUSTOM), sourceConflict, conflictSources, missingDailyCost。

8.2 submitted 集合与索引

集合 my_frozen_monthly_cost_submitted：根字段与 saved 的业务快照大致一致，dataStatus 固定 2，但厂区项不保存 dailyCosts 和冲突/缺日成本告警，提交后的日级追溯能力弱于 saved。两个集合都要求部分唯一索引：{specCode: 1, batchMonth: 1}，unique: true，partialFilterExpression: {isDeleted: 0}。saved 还应有 batchMonth、factories.factoryCode、frozenAttribute 索引。

8.3 迁移顺序

全新数据库：执行 mongodb_collections_init.js 创建集合和索引，再以 revision3 validator 为最终口径。已有旧集合：备份后按现网版本评估并执行 revision2、revision3。revision2：submitted 允许且要求状态 2；补 threeClass* → thirdClass*。revision3：属性改为字符串 frozenAttribute，允许金额存在 decimal/double/int/long/null，迁移 frozenProperty 和三级命名。

两份 revision 当前在本地 Git 状态中是未跟踪文件，无法由代码证明已在任何环境执行。初始脚本的 dailyCost validator 只允许 decimal，而当前实现可能为缺成本日写 null；最终应以 revision3 和实际运行数据验证 validator 是否兼容。

  1. 触发月度计算，确认状态 0 saved 产生；
  2. /page 查询，确认分类、属性、根层和 factories；

12. 当前实现风险与复现注意事项

级别现状影响
严重服务端未校验"冻品运营负责人"、上月和时间窗可绕过前端直接编辑、提交、重算、查明细
严重单厂更新无 expectedUpdateTime CAS并发编辑不同厂区时，厂区值可能正确但根层汇总被旧快照覆盖

14. 最终记忆主线

一句主线：三源日成本 + BI 日重量 + 鲜品月均价 + 产品主数据 → 定时计算厂区/根层月成本 → Mongo saved → Vue 动态厂区表 → 免冻品人工调整 → submitted 整月快照。
  1. 页面"确认"只是内存草稿，"保存"才逐条调用 /edit；"提交"锁定整月。
  2. 月成本核心是正入库量加权，无正重量才做算术平均；跨源优先级为 CUSTOM > FIXED > COEFFICIENT。
  3. 当前服务端没有业务角色和时间窗保护，计算就绪、导出、批量定制品查询也尚未完成，复现时必须保留这些真实边界。

时效边界：本报告基于 2026-07-27 的代码基线（三个工程各自的分支与提交号见第 1 章），描述的是"提交 + 本地工作区"的组合。无法由代码证明的网关、Nacos、数据库连接、XXL-JOB 配置均标注"环境待确认"；设计文档中尚未落地的方案（计算就绪元数据、真正导出、定制品批量查询）不作为现状。
