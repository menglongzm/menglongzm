## 1. 结论与范围

“月度入库成本”不是一个孤立的 Vue 页面，而是一条跨 3 个工程、4 类存储/数据源和 1 个调度平台的业务链：

```text
用户浏览器
  -> Vue 2 月度成本页
  -> Axios /api 网关请求
  -> frozen-cost-accounting 成本服务
       -> MongoDB：月度 saved / submitted
       -> MySQL：产品规格、分类、冻品属性
       -> Feign -> MDM 服务
                    -> Hologres BI 日入库重量
                    -> Hologres 鲜品自然月均价
                    -> Hologres SAP ZCO116D 定制品日成本
       -> MongoDB：定值/系数已提交日成本
  <- 分页 VO（factories 数组）
  -> 前端把 factories 透视为动态厂区列

XXL-JOB 每月 2 日 07:00
  -> frozenMonthlyCostCalcJob
  -> FrozenMonthlyCostCalcHandler
  -> 生成/重算上月 saved 数据
```

本文覆盖当前实现中的查询与筛选、动态厂区列、前端草稿、整体/单厂编辑、批量保存、整月提交、定时计算、日成本三源合并、BI 加权、鲜价校验、Mongo 双集合、下拉接口、临时重算与日明细接口、构建部署和测试现状。

本文不把设计文档中尚未落地的方案当作现状。特别是计算就绪元数据 `calcReady/dataReady/editable/notReadyReason`、真正的导出、定制品批量查询均未在当前代码中实现。

### 3.6 编辑弹窗与强校验

编辑分两种模式：

- 厂区编辑：点击厂区成本，携带 `factoryCode`；
- 整体编辑：点击“整体编辑”，不携带 `factoryCode`，后端把同一成本写入全部厂区。

进入编辑前依次检查：负责人、时间窗口、上月、未提交、免冻品、目标厂区存在，见 `monthlyCost/index.vue:798-834`。已提交状态为 `dataStatus === 2`。

弹窗字段见模板 `94-137`：规格、月份、厂区/范围、系统初算成本、月度成本、修改原因。整体初算展示采用所有厂区 `originalCost` 的最高值，见 `849-855`，但真正校验会遍历根层和每个厂区。

输入先删除所有非数字和小数点字符，再限制两位小数，见 `1077-1101`。注意：粘贴 `-10` 会被清洗成 `10`，这是当前行为。最终正则要求 `^\d+(\.\d{1,2})?$`，见 `1103-1121`。

前后端一致的强规则：

1. 仅免冻品可编辑；
2. 已提交不可编辑；
3. 修改原因必填；
4. 成本非负、后端 `HALF_UP` 保留两位；
5. 修改成本不得低于系统初算成本；
6. 当鲜品价高于月度成本时，差额不得超过五档阈值。

五档按“待修改月度成本”选档：

| 月度成本区间（元/kg） | 鲜价最多高出 |
|---|---:|
| `< 10` | 0.5 |
| `[10, 20)` | 0.8 |
| `[20, 30)` | 1.0 |
| `[30, 40)` | 2.0 |
| `>= 40` | 3.0 |

前端实现见 `monthlyCost/index.vue:1133-1223`，后端实现见 `MonthlyCostValidator.java:91-127`。鲜价为空，或鲜价不高于修改后成本时跳过价差校验。

### 3.7 前端草稿与批量保存

弹窗“确认”不调用接口，只写入内存 `pendingEdits`，见 `monthlyCost/index.vue:1224-1269`。草稿键：

```text
整体：batchMonth|specCode|R
厂区：batchMonth|specCode|F|factoryCode
```

每项保存 `mode/batchMonth/specCode/factoryCode/factoryName/monthlyCost/editReason/originalCost/confirmedAt`，见 `622-661`。

同一规格同时存在整体和厂区草稿时使用 LWW（Last Write Wins）：比较 `confirmedAt`，时间更晚者决定该厂区的页面展示，见 `663-674`。

保存队列算法见 `729-776`：

1. 按 `batchMonth|specCode` 分组；
2. 有整体草稿时先调用整体 `/edit`；
3. 不晚于整体草稿的厂区草稿被整体覆盖，整体成功后一起清除；
4. 晚于整体草稿的厂区草稿按确认时间升序继续调用 `/edit`；
5. 没有整体草稿时，厂区草稿按确认时间升序保存。

`saveData()` 串行执行队列，见 `1001-1076`。成功项从草稿删除并重新查询；失败项保留。允许“部分成功”，最多在提示中展示前三条失败。没有服务端批量保存接口。

草稿在同月查询/翻页后通过 `mergePendingIntoRows()` 回显。切月、重置、浏览器关闭和子组件 `beforeRouteLeave` 有丢弃提示，见 `300-339`、`777-797`。但父 tab 的 `handleBeforeLeave()` 只保护 fixed/coeff，见 `frozenCostAccounting.vue:117-140`；从 monthly tab 切到同页其他 tab 时，monthly 子组件可能被 `v-if` 销毁而没有可靠提示。

## 5. 成本服务实现

### 5.1 分层与调用关系

```text
FrozenMonthlyCostController
  -> FrozenMonthlyCostServiceImpl
       -> MonthlyCostValidator
       -> MyMonthlyCostSavedRepository / MongoTemplate
       -> MyMonthlyCostSubmittedRepository

FrozenMonthlyCostCalcJob / 临时 calc Controller
  -> FrozenMonthlyCostCalcHandler
       -> 定值 submitted Mongo
       -> 系数 submitted Mongo
       -> MDM Feign：ZCO116D / BI / 鲜价
       -> 产品主数据 Mapper
       -> 月度 saved Repository
```

### 5.2 状态机

```text
计算生成 -> 0 SYSTEM_INITIAL（系统初算）
编辑成功 -> 1 MANUALLY_EDITED（人工修改）
整月提交 -> 2 SUBMITTED（已提交）
```

重算规则：新规格插入；已有状态 0 可覆盖；状态 1/2 跳过，避免覆盖人工修改或已提交数据。状态 2 禁止编辑并被提交锁定。

### 5.3 单厂编辑

核心见 `FrozenMonthlyCostServiceImpl.java:123-213`：

1. 检查规格、月份、成本必填；
2. 按 `specCode + batchMonth + isDeleted=0` 查 saved；
3. 检查未提交、免冻品；
4. 原因 trim 后必填，成本 `HALF_UP` 两位；
5. 找目标厂区；
6. 校验不低于厂区 `originalCost`；
7. 校验厂区鲜价五档；
8. 内存替换目标厂区，重算根层成本/重量/鲜价；
9. 原子更新目标数组元素及根层字段，状态改为 1。

Repository 条件见 `MyMonthlyCostSavedRepository.java:108-142`：规格、月份、未删除、状态不为 2、厂区存在。它没有 `expectedUpdateTime` 条件。

### 5.4 整体编辑

不传 `factoryCode` 时：

1. 把相同成本和原因写入每个厂区；
2. 对每个厂区执行初算下限和鲜价五档校验；
3. 重算根层；
4. 用 `updateTime == expectedUpdateTime` 作为乐观锁，整体替换 factories；
5. 状态变为 1。

整体更新 CAS 见 `MyMonthlyCostSavedRepository.java:144-175`。

### 5.5 根层汇总

厂区聚合到根层时：

- 有正 `monthlyInWeight`：按厂区月入库量加权；
- 所有厂区无正重量：对非空厂区值做算术平均；
- 金额保留两位，`RoundingMode.HALF_UP`；
- 根层 `originalCost` 是系统初算快照，人工编辑不覆盖。

### 5.6 整月提交与事务

`FrozenMonthlyCostServiceImpl.java:215` 起使用 `@Transactional(rollbackFor=Exception.class)`：

1. 按月份查全部有效 saved；
2. 拒绝空月、已提交、非法状态、无厂区数据；
3. 根层和每个厂区复验成本非空、初算非空、不得低于初算；
4. **不复验鲜价差**，因为系统初算可能天然超阈；
5. submitted 若该月已有快照则拒绝；
6. 每条 saved 转为 submitted 快照并插入；
7. 批量把该月 saved 的状态 0/1 更新为 2；
8. 实际锁定数不等于预期数则抛异常，使整月回滚。

Mongo 事务管理器在 `*-start/src/main/java/.../config/MongoTransactionConfig.java:15-20` 注册。MongoDB 必须是副本集或支持事务的分片集群；standalone Mongo 无法提供该事务语义。

### 5.7 服务端授权现状

Service 注释明确写着角色、2 日 07:00 和仅上月均由前端负责，见 `FrozenMonthlyCostServiceImpl.java:126`、`222`。`MonthlyCostValidator.assertEditableDay/assertPreviousMonth` 已废弃且为空操作，见 `MonthlyCostValidator.java:37-51`。

因此 Controller/Service 当前没有月度业务角色和时间窗强校验。能通过平台基础认证直接调用接口的主体可绕过页面按钮调用 `/edit`、`/submit`、`/calc` 和 `/dailyCostDetail`。这是当前实现事实，不应在复现时误认为前端权限已形成安全边界。

## 6. 月度自动计算

### 6.1 调度入口

`FrozenMonthlyCostCalcJob.java:14-57`：

- Handler 名：`frozenMonthlyCostCalcJob`；
- 注释 Cron：`0 0 7 2 * ?`；
- 业务时区：`Asia/Shanghai`；
- 默认计算上月；
- XXL-JOB 参数非空时覆盖月份，可用于历史重跑；
- 异常返回 `ReturnT.FAIL`。

Cron 只存在于代码注释，真正调度必须在 XXL-JOB 管理端配置。

### 6.2 日成本来源与优先级

Handler 读取三种来源：

| 来源 | 数据 | 来源标记 |
|---|---|---|
| 定值成本 submitted | `fixedCost` | `FIXED` |
| 系数成本 submitted | `cost` | `COEFFICIENT` |
| MDM ZCO116D | `inWahseCost` | `CUSTOM` |

同一天、同规格、同厂区：

- 同源重复：整月计算失败；
- 跨源冲突：按 `CUSTOM > FIXED > COEFFICIENT` 选赢家；
- 冲突信息写入 `DailyCostItem.sourceConflict/conflictSources`，厂区写摘要告警。

定制品接口按自然月逐日调用 28 至 31 次，只接纳规格编码以 `2` 或 `4` 开头的记录。根目录《定制品日度成本批量查询改造方案》尚未落地。

### 6.3 厂区月成本公式

对一个 `规格 + 厂区`：

```text
起始日 = 本月首个存在有效日成本的日期
扫描区间 = 起始日 .. 月末

若存在“日成本非空 且 日入库量 > 0”的日期：
  月成本 = Σ(日成本 × 日正入库量) / Σ(日正入库量)
  monthlyInWeight = 实际参与公式的正入库量之和

若没有任何正权重日期，但存在有效日成本：
  月成本 = 有效日成本的算术平均
  monthlyInWeight = 0

结果 = HALF_UP 保留 2 位
```

若某日有正入库量但缺日成本，该日重量被排除并写 `missingDailyCostWarning`。首个成本日之前的重量完全不扫描。因此文档中的 `monthlyInWeight` 不是 BI 全月净入库总量，而是成功参与计算的正重量。

### 6.4 根层公式

同规格跨厂区：

```text
根层月成本 = Σ(厂区月成本 × 厂区参与重量) / Σ(厂区参与重量)
根层鲜价   = Σ(厂区鲜价 × 厂区参与重量) / Σ(厂区参与重量)
```

若全厂区无正重量，则分别对非空厂区月成本、鲜价做算术平均。根层 `originalCost` 保存系统初算结果；`monthlyCost` 初始等于它。

### 6.5 产品主数据与冻品属性

成本服务从 MySQL 产品主数据补充名称、二/三/四级分类和状态。规格要求产品启用、分类有效且 `one_class_code='11'`。主要 SQL：

- `MyBaseProductSpecMapper.xml:190` 附近：`my_base_product_spec JOIN my_product_class`；
- `MyMdProductSpecExpandMapper.xml:107` 附近：`my_md_product_spec_expand.frozen_property`。

冻品属性映射：`frozen_property == 1 -> 免冻品`；其余值和缺失 -> `非免冻品`。只有免冻品允许人工编辑。

## 7. MDM 三类数据接口

### 7.1 BI 日入库重量

调用链：

```text
成本 Feign POST /api/frozen/bi-inbound-weight/query
  -> BiInboundWeightController.java:20
  -> BiInboundWeightServiceImpl.java:35
  -> @DS(MYRS_BIGDATA) BiInboundWeightMapper
  -> BiInboundWeightMapper.xml:5
```

请求：

```json
{
  "batchMonth": "2026-06",
  "startDate": "2026-06-01",
  "endDate": "2026-06-30"
}
```

Service 手工校验非空、严格日期格式、起止顺序，并要求范围完整覆盖 batchMonth 的自然月。

响应项：`inboundDate, specCode, factoryCode, netWeightKg`，单位 kg。

数据表：`rs_ads.ads_yy_bi_sale_froze_rcpt_detail_di`。粒度为日期 + 产品 + 厂区。查询范围 `[startDate, endDate + 1 day)`。当前聚合：

```sql
MAX(sum_out_in_wahse_wgt) AS netWeightKg
```

不是 `SUM`。这一口径假设源字段是重复快照而非可累加明细。SQL 不过滤零/负值；计算消费者只使用 `> 0` 的重量。

BI 调用异常、失败响应、空必填字段会使整月计算失败。

### 7.2 鲜品自然月均价

调用链：

```text
成本 Feign POST /api/frozen/fresh-monthly-price/query
  -> FreshMonthlyPriceController.java:23
  -> FreshMonthlyPriceServiceImpl.java:35
  -> FreshMonthlyPriceMapper.xml:5
```

请求：`{"batchMonth":"2026-06"}`。响应项：`batchMonth, comCode, prodCode, monthlyAvgPrice`，单位元/kg。

数据表：`rs_ads.ads_hs_api_gas_prc_di`。范围 `[月初, 下月月初)`。公式：

```sql
SUM(inv_pre * factory_product_weight)
/
NULLIF(SUM(factory_product_weight), 0)
```

SQL 过滤价格非空、重量非空且大于 0、厂区/产品编码非空。

鲜价调用失败不会阻断月成本计算，而是降级为空映射。结果仍可落库，但后续编辑会因鲜价为空而跳过价差规则。

### 7.3 SAP ZCO116D 定制品日成本

该接口不直接调用 SAP，而是查询已同步到 Hologres 的表。

```text
POST /api/frozen/sap-zco116d/query?batchDate=yyyy-MM-dd&specCode=可选
  -> SapZco116dController.java:23
  -> SapZco116dServiceImpl.java:20
  -> SapZco116dMapper.xml:6
```

响应项：`dt, prodCode, prodName, comShortName, inWahseCost`。

数据表：`rs_ads.ads_hs_api_froze_pos_co116d_df`。有效期条件：

```sql
lock_start_date <= batchDate
AND lock_end_date >= batchDate
```

可选规格条件是 `prod_code LIKE '%specCode%'`。SQL 无聚合、无去重；若有效期重叠导致同源重复，消费者会判整月失败。

`comShortName` 在成本服务通过精确名称映射到十厂编码，不 trim、无别名；无法映射即整月失败。BI `factoryCode` 和鲜价 `comCode` 则被直接假定已经是同一标准编码域。

### 7.4 MDM 数据源

三个 Mapper 都通过 `@DS(MyDataSourceConstant.MYRS_BIGDATA)` 使用常量值 `myrs_bigdata_dev`。生产也必须注册该逻辑数据源键，或在部署前修改命名。需要在 Nacos/启动配置提供 JDBC URL、驱动、账号、密码、连接池参数，并授予三个 `rs_ads` 表 SELECT 权限。

## 12. 当前实现风险与复现注意事项

| 级别 | 现状 | 影响 |
|---|---|---|
| 严重 | 服务端未校验“冻品运营负责人”、上月和时间窗 | 可绕过前端直接编辑、提交、重算、查明细 |
| 严重 | 单厂更新无 `expectedUpdateTime` CAS | 并发编辑不同厂区时，厂区值可能正确但根层汇总被旧快照覆盖 |
| 高 | 前端窗口写成 `day===2 && hour>=7` | 实际仅 2 日当天开放，不是 2 日后持续开放 |
| 高 | 前端使用浏览器时区 | 非东八区用户状态不同于 Job 的上海时区 |
| 高 | 没有计算就绪元数据 | Job 延迟/失败可能表现为空数据或错误“已就绪” |
| 高 | Mongo 事务依赖副本集和迁移实际执行 | 环境不满足时整月提交原子性不成立 |
| 高 | `/calc`、`/dailyCostDetail` 临时接口仍在 | 重计算占 Web 线程，且暴露内部日级数据 |
| 高 | `/export` 是空实现 | 前端 API 声明 blob，但后端不会生成文件 |
| 高 | 定制品按天 Feign 28-31 次 | 慢、易受单日调用失败影响，批量方案未落地 |
| 中 | 鲜价失败静默降级 | 计算继续，但编辑价差保护被跳过 |
| 中 | submitted 不存 dailyCosts/告警 | 提交后审计追溯信息变少 |
| 中 | 页内切换 monthly tab 草稿保护不可靠 | 未保存修改可能丢失 |
| 中 | 输入清洗把 `-10` 变成 `10` | 用户负号输入被改变而不是明确拒绝 |
| 中 | BI 使用 MAX 而非 SUM | 依赖源数据为重复快照的业务假设 |
| 中 | 数据源键硬编码 `myrs_bigdata_dev` | 生产配置可能误路由 |
| 中 | 配置/手工测试中发现明文凭据 | 应立即轮换并迁移到秘密管理；本文未复述值 |

## 14. 最终记忆主线

**一句主线：** 三源日成本 + BI 日重量 + 鲜品月均价 + 产品主数据 -> 定时计算厂区/根层月成本 -> Mongo saved -> Vue 动态厂区表 -> 免冻品人工调整 -> submitted 整月快照。

**三个关键点：**

1. 页面“确认”只是内存草稿，“保存”才逐条调用 `/edit`；“提交”锁定整月。
2. 月成本核心是正入库量加权，无正重量才做算术平均；跨源优先级为 `CUSTOM > FIXED > COEFFICIENT`。
3. 当前服务端没有业务角色和时间窗保护，计算就绪、导出、批量定制品查询也尚未完成，复现时必须保留这些真实边界。
