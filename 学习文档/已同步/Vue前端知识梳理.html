Vue 前端知识梳理：从界面操作到后端请求

基于"报价审批页产品名称筛选"代码整理，目标是建立一套可迁移的 Vue 阅读框架，而不是逐条记忆语法。核心循环 + 四条连接线 + 五步阅读法，即可读懂大多数 Vue 2 业务页面。

范围：以 Vue 2 + Element UI / Avue 的组件式页面为主（示例组件：el-select、avue-crud、el-dialog）。

1. 一句话定位与主线

Vue 页面是一个持续循环的数据系统：数据决定界面，操作修改数据，数据变化自动刷新界面。开发者只需修改状态，Vue 负责同步界面。

JavaScript 提供数据
  -> template 根据数据渲染界面
  -> 用户操作界面
  -> v-model 更新数据，事件调用函数
  -> 函数请求后端
  -> 后端结果写回数据
  -> Vue 自动刷新界面

在本次产品筛选功能中，这条主线具体是：

加载全部产品
  -> 用户按名称或编码过滤候选项
  -> 选择具体产品
  -> productCode 写入查询条件
  -> 请求审批列表
  -> tableData 更新
  -> 表格自动刷新

3. 单文件组件的三个部分

<template>
  页面结构和事件连接
</template>

<script>
  页面数据和业务逻辑
</script>

<style>
  页面样式
</style>
部分职责类比
template展示什么、监听什么操作界面说明书
script数据从哪里来、操作后做什么控制中心
style元素如何排列和显示装修规则

阅读页面时，不建议从第一行逐行读到底。更有效的顺序：

  1. 在 template 中找到用户入口；
  2. 找到入口绑定的字段和函数；
  3. 到 data/props/methods 中追踪；
  4. 最后追踪 API 和返回数据。

4. template 与 JavaScript 的四条核心连接线

4.1 {{ value }}：把数据展示为文字

待我审批({{ toDoNum }})

当 JavaScript 执行 this.toDoNum = 25，页面自动变为"待我审批(25)"。记忆：双花括号负责显示文字。

4.2 :属性="value"：把 JavaScript 数据交给组件

<avue-crud :data="tableData" :table-loading="loading" />
  • tableData 决定表格显示哪些记录；loading 决定是否显示加载状态。
  • 冒号是 v-bind: 的简写：data="tableData" 传普通字符串，:data="tableData" 传 JavaScript 变量的值。

记忆：冒号负责向组件传入动态数据或函数。

4.3 v-model="value"：控件值与数据双向同步

<el-select v-model="searchForm.productCode" />
用户选择产品      -> searchForm.productCode 自动更新
代码修改 productCode -> 下拉框选择状态自动更新

v-model 主要负责保存值，本身不等于"发起查询"。查询通常由事件绑定触发。记忆：v-model 负责界面值和状态之间的双向连接。

4.4 @事件="method"：事件发生时调用函数

<el-button @click="search">查询</el-button>
<el-select @change="search" />
<avue-crud @current-change="getTableData" />

分别表示：点击按钮 → search()；下拉值改变 → search()；当前页码改变 → getTableData()。@ 是 v-on: 的简写。记忆：@ 负责把用户操作连接到函数。

四条连接线总结

模板语法作用
{{ value }}显示数据
:prop="value"给组件传动态数据或函数
v-model="value"控件值与状态双向同步
@event="method"事件发生时调用函数

5. template 中的数据来自哪里

模板可直接使用以下四类内容，不需要写 this：

来源作用示例
data()组件自己的可变状态searchForm、tableData
props父组件传入的数据searchType、areaOptions
computed根据其他状态计算的值jobNo
methods可被事件或其他函数调用的方法search()

JavaScript 方法内部要写 this.productOptions；模板中直接写 v-for="item in productOptions"，因为模板天然处在当前组件的作用域中。

5.1 data()：组件自身状态

data() {
  return {
    allProductList: [],
    productOptions: [],
    searchForm: {
      productCode: ''
    },
    tableData: []
  }
}
  • allProductList 保存完整产品列表；productOptions 保存当前展示的候选项；
  • searchForm.productCode 保存用户选中的产品编码；tableData 保存审批表格记录。

5.2 props：父组件传入的数据

<to-approval :searchType="1" :areaOptions="areaOptions" />
props: {
  searchType: Number,
  areaOptions: Array
}

数据流为：父组件数据 → 标签属性 → 子组件 props → 子组件 template/methods。有冒号的 :searchType="1" 传入数字 1；没有冒号的 searchType="1" 传入字符串 '1'。

5.3 临时变量：v-for 与插槽

<el-option v-for="item in productOptions" />

item 是循环中的当前元素，只在这一段模板中有效。

<template slot-scope="{ row }">
  <el-button @click="handle(row)">处理</el-button>
</template>

row 是表格组件提供的当前行数据，并非来自 data()。

6. 函数在什么时候被触发

Vue 页面中的函数主要通过四种方式触发。

6.1 生命周期自动触发

created() {
  this.getTableData()
}

mounted() {
  this.getAllProductList()
}
  • created：组件数据和方法准备好后，由 Vue 自动调用（本页：查询审批列表）；
  • mounted：组件已经放到页面后，由 Vue 自动调用（本页：加载产品候选项）。

6.2 界面事件触发

@click="search"
@change="search"
@current-change="getTableData"

用户点击、选择或翻页后，组件发出事件，Vue 按模板绑定调用对应方法。

6.3 组件按约定调用回调

<el-select :remote-method="productProductData" />

这里是把函数交给 Element UI。用户输入搜索文字时，el-select 按组件约定调用 productProductData(当前输入文字)。例如输入"肉丝"：productProductData('肉丝')。

6.4 JavaScript 方法之间主动调用

search() {
  this.getTableData()
}

这里不是 Vue 自动触发，而是 search() 主动调用另一个方法。

7. 函数参数是如何获得值的

核心规则：谁调用函数，通常就由谁提供实参；函数形参按位置接收。

  1. 模板显式传入：@click="handle(row)" → 模板中的当前行 row 成为函数的第一个参数。
  2. 组件自动传入：:remote-method="productProductData" → Element UI 自动传入当前搜索文字。事件也可能自动携带值，但函数可以不接收（@change="search" 中事件值被忽略，改为从 this.searchForm 读取统一状态）。
  3. JavaScript 数组方法传入：map((item) => ...)、filter((item) => ...) 每次把当前数组元素赋给 item。
  4. Promise 传入接口响应：apiGetApprovalPage(params).then((res) => { this.tableData = res.data.data.records })。
  5. 对象解构参数：headerCellClassName({ columnIndex }) 等价于先接收整个上下文对象再取 columnIndex。
  6. 不使用参数，读取组件状态：
getTableData() {
  const params = {
    ...this.searchForm,        // 来自 data()
    searchType: this.searchType, // 来自 props
    page: this.page.currentPage // 来自 data()
  }
}

这解释了为什么选择产品后，search() 即使不接收 productCode 参数，也能查询到正确结果：v-model 已经提前把值写入 this.searchForm.productCode。

8. 列表与表单的两个关键机制

8.1 v-for：数组驱动界面

<el-option
  v-for="item in productOptions"
  :key="item.value"
  :label="item.label"
  :value="item.value"
/>

如果 productOptions 有三个元素，Vue 就生成三个选项。数组过滤后只剩一个元素，界面也自动只剩一个选项。productOptions 改变 → v-for 重新计算 → 下拉选项更新。

8.2 展示值和实际值分离

{
  label: '冻猪肉丝H（10kg）',
  value: 'PRD001'
}
  • label 给用户看；value 给程序和后端使用。
  • 用户选择名称后，searchForm.productCode = 'PRD001'。

因此本功能是：用户按名称寻找产品，但后端按编码精确查询。

9. 响应式更新：数据为什么能自动刷新界面

Vue 会追踪模板使用了哪些状态。例如模板 <avue-crud :data="tableData" />，接口返回后执行 this.tableData = res.data.data.records，Vue 检测到 tableData 变化就更新表格，不需要手工调用"刷新表格"。

toDoNum 改变         -> 标题数量更新
productOptions 改变  -> 产品候选项更新
loading 改变         -> 加载状态更新
page.total 改变      -> 分页总数更新

这就是 Vue 的核心思路：开发者修改状态，Vue 负责同步界面。

10. 分页为何要区分筛选与翻页

search() {
  this.page.currentPage = 1
  this.getTableData()
}
@current-change="getTableData"
操作调用原因
修改筛选条件search()新结果应从第一页开始
修改每页条数search()页数结构改变，应回第一页
点击第 2 页getTableData()必须保留用户选择的新页码

如果翻页也调用 search()，第 2 页会立即被重置为第 1 页。

11. 父子组件的两种通信方向

11.1 父组件向子组件传数据：props

<to-approval :searchType="1" />

方向：父组件 → props → 子组件。

11.2 子组件向父组件发事件：$emit

this.$emit('handle', row)
<to-approval @handle="handle" />

方向：子组件当前行 row → $emit → 父组件 handle(row)。

父组件还可以通过 ref 主动调用子组件方法：this.$refs.toApproval.search()。当前场景用于审批处理成功后刷新列表。

13. 如何阅读一个陌生的 Vue 页面

下图回答：按什么顺序追踪，才能闭合"界面 → 函数 → 接口 → 数据 → 界面"的完整链路？

  1. 第一步：找界面入口——搜索 @click、@change、v-model、:remote-method，确定用户操作会触发什么。
  2. 第二步：找到绑定的数据——例如 v-model="searchForm.productCode"，到 data() 中查看初始结构，并搜索谁会修改、读取它。
  3. 第三步：找到事件函数——例如 @change="search"，到 methods 中找到 search()，再继续追踪其内部调用。
  4. 第四步：追踪 API——search() → getTableData() → apiGetApprovalPage(params) → API 文件中的 URL。
  5. 第五步：追踪返回数据——检查接口结果写入了哪个状态（this.tableData = records），再回到模板找 :data="tableData"，闭合链路。

15. 进阶知识点

15.1 条件渲染：v-if vs v-show

特性v-ifv-show
原理条件 false → 元素不在 DOM 中元素始终在 DOM，只是 display: none
切换开销高（创建/销毁）低（CSS 切换）
适用场景组件重、切换不频繁切换频繁

v-if / v-else-if 互斥渲染：从上往下判断，第一个为 true 的渲染，同一时间只有一个组件存在。

15.2 路由系统

  • 两层 <router-view /> 嵌套：第一层在 App.vue（切换"登录页"与"主布局框架"）；第二层在主布局内切换具体业务页面。
  • 动态路由：路由不是写死的，而是登录后从后端拉取菜单数据动态注册，核心方法 Router.$avueRouter.formatRoutes(menuAll, true)。
  • <keep-alive> 缓存：包裹 <router-view /> 时，切走的页面不销毁，切回来直接恢复。

15.3 Flex 布局核心属性

display: flex;                  /* 开启 flex 布局 */
justify-content: space-between; /* 子元素两端对齐 */
align-items: center;            /* 子元素垂直居中 */
flex: 1;                        /* 占满剩余空间 */
flex: none;                     /* 不伸缩，保持原始宽度 */
min-width: 0;                   /* 防止 flex 子项内容撑开溢出 */

15.4 avue-crud 表格组件

属性作用类比
:option="tableOption"定义表格结构（列、样式）骨架
:data="tableData"表格数据（数组，每条数据是一行）血肉
:page.sync="page"分页信息（当前页、每页条数、总数）翻页器
  • column 中的 prop 必须和数据对象的字段名严格一致（包括大小写）；不一致不会报错，但该列显示空白。
  • 某列需要特殊展示（颜色、按钮、条件渲染）时用 slot: true 标记，再在 template 中用 <template slot="prop名"> 覆盖默认渲染。
  • 数据流链路：created() → 调用 API → 赋值 tableData → Vue 响应式 → 表格自动刷新。

15.5 弹窗（el-dialog）

属性作用
:visible.sync双向绑定控制弹窗显隐
:append-to-body把弹窗 DOM 插入 <body> 下，避免被 overflow: hidden 裁切
:destroy-on-close关闭时销毁内部组件，下次打开重新创建
:before-close关闭前的回调，常用于设置 visible = false

15.6 ::v-deep 样式穿透

Vue 的 <style scoped> 只影响当前组件；::v-deep 告诉 Vue"穿透作用域，去修改子组件内部的样式"，常用于覆盖 Element UI 组件的默认样式。

15.7 其他常用知识点

知识点说明
@/ 路径别名指向 src/ 目录，在 jsconfig.json 中配置
computed 计算属性依赖的数据变化时自动重新计算，有缓存
$bus.$emit事件总线，跨组件通信（不经过父子关系）
mapGettersVuex 辅助函数，把 store 中的 getter 映射为组件的 computed
ref给子组件一个引用，父组件可通过 this.$refs.xxx 直接访问子组件实例
lazy（el-tab-pane）懒加载，第一次切到该 Tab 时才渲染内容
防竞态（fetchFlag / searchRequestId）用递增序号或时间戳标记最新请求，丢弃过期的响应数据

17. 记忆卡片与自测

一条核心循环

状态 -> 渲染界面 -> 用户操作 -> 修改状态/调用函数 -> 请求后端 -> 写回状态

四条模板连接线

{{ }}    显示数据
:prop    传入动态数据或函数
v-model  控件与状态双向同步
@event   事件触发函数

四类常见函数参数

模板显式传入：handle(row)
组件自动传入：productProductData(keyword)
JS API 传入：map(item)、then(response)
组件状态提供：this.searchForm、this.page

产品筛选主线

接口产品 { productName, productCode }
  -> 下拉选项 { label, value }
  -> 用户选择产品名称
  -> v-model 保存 productCode
  -> change 调用 search
  -> getTableData 组装请求
  -> 后端精确查询
  -> tableData 更新表格

三个自检问题

  1. v-model 和 @change 各自负责什么，为什么经常一起出现？
  2. search() 没有参数，为什么仍能取得最新的产品编码？
  3. 接口返回后只修改 tableData，为什么表格会自动更新？
参考答案
  1. v-model 负责把控件值写入状态（双向同步）；@change 负责在值变化后触发查询。先存值、再查询，所以经常成对出现。
  2. 因为 v-model 已提前把选中值写入 this.searchForm.productCode，函数从组件状态读取，无需参数传递。
  3. 模板中 :data="tableData" 建立了响应式依赖，Vue 检测到状态变化后自动重渲染表格。
