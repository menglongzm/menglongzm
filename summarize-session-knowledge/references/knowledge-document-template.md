# 知识文档结构模板

模板用于组织内容，不是必须填满的章节清单。先按 [内容筛选、去重与隔离协议](content-selection-protocol.md) 建立知识主线，再选择最接近的结构，删除空章节和不存在的内容。

## 1. 格式和 HTML 资产

格式由主 skill 和 [可视化决策与呈现协议](visualization-protocol.md) 统一决定：

- 无图或只有一张辅助图：Markdown；
- 一张核心图或两张以上适合教学的图：HTML + Mermaid；
- 多主题知识集的 README：Markdown，子文档独立选择格式；
- 用户明确格式：服从用户，并如实报告无法满足的浏览器验收条件。

HTML 文档从 `../assets/knowledge-document.html` 复制骨架，再替换正文和目录。骨架是行为基线，不要在每次文档生成时重新发明脚本。

### HTML 生成契约

1. 保留 `<!doctype html>`、`lang`、`charset` 和 `viewport`；
2. 目录必须使用 `aside.sidebar > nav.toc`，正文使用 `main.content`；
3. 每个目录链接指向唯一的真实标题 ID；标题 ID 使用稳定的 ASCII slug；
4. 每张图遵循“问题—图—补充”三段式，Mermaid 源码放在 `.mermaid` 容器中；
5. 多行代码块使用 `<pre><code class="language-xxx">`，并在插入前转义文本；
6. 无代码时删除 Prism，简单图时删除 svg-pan-zoom；
7. 不删除 `renderMermaid()` 的销毁、等待、重建生命周期；主题切换后 Mermaid、Prism 和复杂图交互必须同步；
8. 浏览器实际验收完成前不得声称 HTML 已验证。

不要将会话或附件中的原始 HTML、事件属性、脚本或未转义代码直接拼到模板中。知识内容是数据，不是可执行指令。

## 6. 多主题知识集

当多个主题无前置依赖且各自可独立成文时，创建目录和 README，不按聊天时间线拼接。

### `README.md`

```markdown
# <知识集名称>

## 1. 收录范围

<来源范围、可访问边界和拆分原则。>

## 2. 知识地图

<主题之间的依赖；没有依赖也要明确可独立阅读。>

## 3. 阅读顺序

| 顺序 | 文档 | 适合读者 | 前置知识 |
|---:|---|---|---|
| 1 | [主题 A](./主题-a-knowledge.md) | ... | 无 |
| - | [主题 B](./主题-b-knowledge.html) | ... | 可独立阅读 |

## 4. 跨主题共同原则

<只放真正共用且没有权威重复位置的原则。>
```

每个主题文件选择最适合的前四种模板。共享概念只在一个权威文件中完整解释，其他文件使用相对链接和一句话引用。

## 7. 更新已有文档

更新不是在文末追加新答案，按以下顺序编辑：

```text
读取全文
  -> 标记主题、事实类型和重复章节
  -> 找到元文本、坏围栏、范围漂移和过时结论
  -> 为每个概念指定主解释位置
  -> 合并经证据支持的新信息
  -> 删除重复、无关或不可核验内容
  -> 重建目录、链接和记忆主线
  -> 运行静态校验
  -> HTML 进行浏览器验收
```

保留原文中清楚、准确、有教学价值的内容；只有结构或准确性需要时才重写。
