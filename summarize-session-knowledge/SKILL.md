# 总结会话知识点

把值得长期保留的内容重新组织为一份**不依赖原会话、不依赖原项目也能理解**的知识文档。目标不是压缩聊天记录，而是完成编辑、归纳和教学重构。

## 触发与边界

### 应触发

- 总结本次会话知识点、整理学习笔记、沉淀复习资料；
- 汇总讨论中的概念、方法、经验、流程、纠正和可迁移结论；
- 将一段讨论改造成独立可读的知识文档、项目知识说明、问题复盘或操作手册。

### 不应单独触发

- 用户只要即时解释、逐行讲解或代码导航，不要生成知识文档；
- 用户要求按 PRD、技术设计或 issue 修改代码；
- 用户要求评审代码、研究外部资料但不要求沉淀文档；
- 用户只要聊天记录压缩、会议纪要或任务状态摘要。

若同一请求既要求解释又要求长期沉淀，先完成必要理解，再按本 skill 生成文档。

## 成品质量标准

成品必须同时满足：

1. **完整**：覆盖当前可见输入中的有效知识，或明确披露不可访问的范围；
2. **去重**：一个规范概念只有一个主解释位置，其他位置只引用或补充新边界；
3. **隔离**：不同主题、抽象层级和事实类型不混写；
4. **独立**：首次接触主题且没看过原会话或原项目的读者可以顺序学习；
5. **准确**：项目事实、需求意图、建议和猜测不被包装成普遍规律；
6. **纯净**：正文没有代理思考、工具过程、权限说明、交付话术或聊天残片；
7. **可复习**：有整体地图、关键区别、记忆主线；内容适合时加入速查和自测；
8. **可验证**：HTML 交付必须有浏览器实测证据，不能以“应该能渲染”代替验证。

## 输入范围与真实性

允许使用：

- 当前上下文中实际可见的用户和助手内容，包括问题、解释、结论、代码、案例和纠正；
- 用户明确指定的本地文档、附件或代码；
- 为核验某个主张而实际读取的一手资料。

严格遵守：

- “所有会话知识”只指当前可见、可读取或可检索的内容。不得假装访问丢失的历史消息；材料不足时交付“部分完成”并列出可操作的补充材料方式；
- 不把为了完成任务而临时获得的工具知识写入正文，除非它本身就是用户要学习的主题；
- 以证据支持的后续纠正为准；无法裁决的冲突标记“待确认”，不以用户坚持或消息顺序代替证据；
- 不复述密钥、token、密码、个人隐私或不必要的本机绝对路径。

## 文档类型路由

根据知识形状选择产物，不按聊天轮次写章节：

| 类型 | 适用场景 | 必要重点 |
|---|---|---|
| 通用学习笔记 | 概念、语言、框架、工具或方法 | 原理、关系、示例、易错点、自测 |
| 项目知识说明 | 特定系统、模块、页面或功能实现 | 适用范围、系统地图、当前实现、代码导航、限制 |
| 问题复盘 | 调试、事故、冲突、失败测试或性能回归 | 现象、根因、修复、验证、预防、可迁移经验 |
| 操作手册 | 需要重复执行的命令、迁移、部署或人工流程 | 前置条件、步骤、验证、失败处理、回滚、风险 |
| 多主题知识集 | 多个彼此独立、各自可成文的主题 | 总索引、阅读顺序、独立篇章、跨文件去重 |

用户明确指定类型时服从；否则以通用学习笔记为默认，只有项目实现本身是学习目标时才使用项目知识说明。多主题知识集是容器：每个子主题仍按自己的内容选择通用笔记、项目说明、复盘或手册。

## 输出格式、位置与命名

按以下顺序选择：用户明确格式 > 文档内容路由 > 默认 Markdown。

| 条件 | 格式 |
|---|---|
| 无图或只有一张辅助图，且文字/代码/表格为主 | Markdown |
| 一张图是核心知识载体 | HTML + Mermaid |
| 有两张或以上适合教学的图 | HTML + Mermaid |
| 用户明确指定格式 | 服从用户；若与浏览器验证要求冲突，说明限制 |

多主题知识集的 README 始终为 Markdown；子文档独立决策格式。保存规则：

1. 用户指定路径优先；
2. 用户要求保存但未指定位置时，保存到当前工作区；
3. 单文档默认命名为 `<topic>-knowledge.md` 或 `<topic>-knowledge.html`；
4. 多主题默认目录为 `<collection>-knowledge/README.md`，子文档使用稳定、可读的主题文件名；
5. 目标已存在时先读取并合并；来源不明的同名文件不覆盖，改用不冲突名称或询问用户；
6. 只要用户要对话内结果，就直接输出，不创建文件；默认只改知识文档，不修改业务代码、配置或测试。

开始组织正文前，读取并执行：

- [内容筛选、去重与隔离协议](references/content-selection-protocol.md)；
- [知识文档结构模板](references/knowledge-document-template.md)；
- [可视化决策与呈现协议](references/visualization-protocol.md)。

## 执行工作流

### 1. 建立范围和证据表

确定主题、读者、输入来源、可访问边界、文档类型、输出位置和是否需要项目复盘/代码导航/操作步骤。只有答案会改变边界、覆盖方式或类型时才提问。

对每个输入路径使用 `scripts/input-classify.mjs` 的 `classifyInput()` 判断是否默认排除（旧产物、缓存、日志、凭据、二进制、skill 自身文件）；用户明确指定且确实是知识来源的可覆盖排除。读取后在内部 InputManifest 中记录路径、类型、编码、大小、哈希、读取状态和来源优先级。禁止空输入或只有过程记录时生成空知识文档；部分读取和编码错误交付为 unverified。

内部建立候选台账，至少记录规范名称、定义、来源、事实类型、证据、核验状态、适用范围、前置知识、归属文件、来源优先级、观测时间、版本基线、时效性、置信度和处理决定。台账 ID 不写入正文。

### 2. 提取、归一化和去重

完整扫描输入后提取：概念和定义、原理和数据流、步骤和命令、对比和边界、公式和状态、纠正、案例、验证方法及安全注意事项。相同核心问题只建立一个知识点；相关但不同、条件不同或风险不同的概念保持独立。

按读者学习依赖排序，不按消息时间排序。每个概念选择一个主解释位置，其他地方只能引用、补充新边界、在综合示例中使用或在速查中压缩。

### 3. 分离事实层

每条内容只进入一层：

1. **通用层**：脱离项目仍成立的定义、机制和方法；
2. **示例层**：帮助观察通用知识的中性或明确标注的项目示例；
3. **项目事实层**：只对特定仓库、版本、业务或环境成立的事实。

项目名、路径、类名、接口、分支、commit、表名和业务编码只有在项目说明、复盘、证据或复现确实需要时保留，并标明“当前实现”“项目示例”或适用基线。未落地设计、推荐方案和环境猜测必须单独标记。

### 4. 组织教学主线

优先使用以下顺序，按事实裁剪：

1. 一句话定位：这组知识解决什么问题；
2. 整体地图、数据流或概念关系；
3. 核心概念的输入、输出、机制、条件和边界；
4. 一个贯穿示例；
5. 易混概念、误区和反例；
6. 速查、3～7 个记忆钩子和自测。

遵循“先整体后局部、先使用后原理、首次出现先解释”。没有真实内容的章节删除；不要为填模板创造会话中不存在的知识。

### 5. 决定可视化和 HTML 能力

读取可视化协议，先判断关系、流程、状态、层级或时序是否真的比等量文字更易懂；不要为了“有图”而画图。每张图只回答一个问题，并使用“问题—图—补充”三段式。调用链用 `sequenceDiagram`，数据关系用 `erDiagram`，状态流转用 `stateDiagram-v2`，决策分支用 `flowchart`，类型错配时改用文字或表格。

HTML 只按需挂载 Mermaid、Prism 和 svg-pan-zoom：

- HTML 含多行代码块时使用 Prism，并为每个代码块标注正确语言；
- 复杂图才使用 svg-pan-zoom，主题切换后销毁旧实例并在新 SVG 渲染完成后重建；
- 使用 `assets/knowledge-document.html` 作为骨架，避免手写不一致的生命周期和响应式逻辑。

### 6. 写入、静态检查和浏览器验收

更新文档先读全文，合并重复、修正过时结论、重建目录和链接，不在文末追加第二份总结。完成后：

1. 运行 `node scripts/validate-knowledge-document.mjs <file>`；需要机器可判断的交付状态时使用 `--json` 模式，输出 `static_status`（pass/fail）和 `delivery_status`（pass/unverified/fail）；
2. 对 HTML 使用浏览器工具实际打开并检查宽屏（至少 1200px）和窄屏（不超过 768px）；
3. 检查 Mermaid 是否全部变成 SVG、节点和文字是否可读、是否横向溢出、目录是否随阅读保持可见、ScrollSpy 是否高亮、主题切换后 Mermaid/Prism/pan-zoom 是否仍工作；
4. 检查浏览器控制台无语法、CDN、Mermaid 或交互错误；
5. 浏览器工具不可用或验证未完成时，只能报告“部分完成”，列出未验证项目，不能声称成品已验证。HTML 静态通过时交付状态为 `unverified`，完成浏览器验收后升级为 `pass`。

### 7. 多主题拆分

不同领域且无学习依赖、各自可独立成文、合并会造成跳转，或用户明确要求隔离时，创建总索引和多个文件。公共概念只在一个权威文件中解释，其他文件用相对链接引用。README 给出收录范围、知识地图、阅读顺序和各文档用途。

### 8. 元文本和风险门禁

正文不得出现模型思考、工具调用、权限模式、任务过程、交付话术、聊天现场指代、整篇嵌套代码围栏或秘密。静态校验器将正文中的对话元文本检测为 error（围栏中的反例不误判），秘密凭据检测为 error（报告时只给类型和位置，不回显值），无实质知识内容的文档检测为 error。高影响操作必须说明影响、只读预检、备份/快照、安全替代、成功验证、恢复路径和不可恢复边界；不能只给命令。具体规则见内容协议。

## 最终自检

- 有效候选知识是否都有落点，删除项是否有原因；
- 未看过原会话和原项目的读者能否从头理解；
- 一个概念是否只有一个主解释位置，速查是否只是压缩；
- 通用层、示例层、项目事实层是否分开；项目约定和猜测是否被正确标记；
- 是否没有代理思考、工具过程、交付话术、秘密或不必要绝对路径；
- 主题是否按学习依赖隔离，README 和内部链接是否正确；
- 命令是否带前提、风险、验证与恢复路径；
- 可视化是否适用、图型匹配、一图一问、三段式、命名一致且不过载；
- HTML 是否只加载实际需要的依赖，CDN 是否固定版本；
- HTML 是否通过静态校验和浏览器实测；未实测不得声称已验证。

## 最终回复

简要报告以下信息，不粘贴整份文档：

```text
执行结果：完成 / 部分完成 / 需要补充材料
- 文档类型：
- 输入范围及不可访问边界：
- 输出格式：Markdown / HTML + Mermaid / 多主题知识集
- 输出文件：
- 主题及拆分结果：
- 可视化：无 / 图类型、知识点和适用性依据
- 已执行处理：提取、去重、事实分层、元文本清理、结构重组、静态校验、浏览器验证
- 证据、版本和时效边界：
- 未覆盖内容及原因：
```

不得声称读取了未访问的历史、文件、代码或外部资料。
