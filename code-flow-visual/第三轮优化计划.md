## 实施步骤

### 1. 强化 FLOW_DATA Schema ✅
修改 `references/flow-data-schema.md`：
- [x] 增加 `paths`：每条路径含条件、有序节点/边列表、终点和 DB 操作数
- [x] 增加 `transactions`：事务入口、成员、事务外操作、提交点和回滚条件
- [x] 增加 result source 语义：`query-result | affected-row-count | in-memory-object | generated-value | response-body`，记录 `consumed`
- [x] 增加 `spawn` 边类型用于异步派生请求
- [x] 增加 URL 映射契约字段
- [x] 扩展证据 basis：增加 `framework-derived | config-scoped`
- [x] 增加规则：同一 Mapper 方法执行多次用独立节点；禁止合并多 DAO/DB 操作

### 2. 修复并增强 Validator ✅
修改 `scripts/validate-flow-data.mjs`：
- [x] 修复 `http.params` 非数组崩溃（改为 `validateHttpParams()` 独立处理）
- [x] 校验 `http.params[].in` 字段
- [x] 校验 `paths` 连续性（放宽为支持子调用返回的 visitedNodes 检查）
- [x] 校验 `transactions` 成员和路径 DB 操作计数
- [x] 校验 DML 默认只产生 `affected-row-count`；声称返回行需 `returnsRows` 证据
- [x] 校验 `spawn` 边不出现在父路径同步返回序列中
- [x] 校验扩展证据 basis
