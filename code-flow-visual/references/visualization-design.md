# 可视化设计规范

本规范把 `FLOW_DATA.flows[].nodes` 与 `edges` 渲染为面向代码审查的双轨证据图。页面的首要任务是让读者核对调用方向、参数流和返回数据，不是展示装饰性架构图。

## 1. 信息层级

页面按以下顺序组织：

1. 标题和一句话摘要
2. 范围、覆盖状态、发现/追踪数量和代码根边界
3. 抽样选择依据
4. flow Tab
5. 播放与轨道控制
6. 当前 flow 的双轨图
7. 未追踪入口清单

`sampled` 和 `partial` 使用警示样式，不能藏在节点详情中。项目范围还要显示模块发现/追踪数量。

## 2. 双轨布局

左轨表示 `direction: request` 的调用方向，使用暖色实线；右轨表示 `direction: return` 的数据方向，使用冷色虚线。`branch` 使用中性点线并显示条件。

```text
层级       请求 / 调用（下行）                  返回 / 数据（上行）
前端       POST /api/orders                     页面接收 OrderView
Controller OrderController.create               Result<OrderView>
Service    OrderService.create                   Entity -> OrderView
DAO        OrderRepository.insert                row -> OrderEntity
终点                 orders / INSERT
```

- 节点的 `depth` 决定水平层级行，`lane` 决定左右轨或折返点。
- 数据库、缓存、外部 API、队列、文件、内存和断链通常为 `turnaround`。
- 同一 depth 有多节点时在所属轨道纵向堆叠，不覆盖卡片。
- 连线只在卡片之间的层间隙和轨道通道走正交折线。
- 展开节点、切换 flow、切换主题和改变视口后都重新读取实际坐标。

## 3. 节点卡片

默认态只显示：层/类型、符号、方法签名和主要功能。点击展开后显示：

- HTTP 方法、URL 与请求参数
- 方法形参：名称、类型、来源与含义
- 数据库系统、表、操作和关键条件
- 返回类型与结构
- 最终 HTTP 状态、Content-Type 和 body 结构
- 进入该节点的调用实参映射或返回数据转换
- 源码路径、行号、符号和证据类型
- 断链原因及 `knownNext`

Controller、Service、数据访问层卡片不得省略签名和参数数组。没有参数时显示“无参数”，不要删除该区域来掩盖未分析。

## 4. 边与标注

边来自 `flow.edges`，不得根据卡片排列顺序猜连接关系。

- 请求边的详情展示 `parameter <- expression`。
- 返回边的详情展示 `before -> after` 与 `action`。
- 分支边显示 `condition`。
- 线上 `label` 保持简短；完整信息放在目标节点的“进入此节点的数据”区域。
- label 使用不透明背景，避免与线和背景混成一团。
- 断链节点不绘制任何出向边；若数据中有出向边，validator 应先拒绝生成。

## 5. 播放语义

播放顺序由 `direction` 和 `order` 决定：

1. 高亮入口。
2. 按 `request` 顺序走到所有已声明终点或关键支线。
3. 按 `return` 顺序从终点回到最终响应。
4. `broken` flow 在断链节点结束，不显示不存在的响应动画。

播放是讲解辅助，不能成为唯一的信息载体。关闭动画或不播放时，全部节点和边仍可直接阅读。

## 6. 视觉系统

默认模板采用中性工程台账底色，方向色只服务于语义：

- 请求：暖橙/铜色，表示向系统内部推进
- 返回：青绿，表示数据向调用方回流
- 断链：红色虚线边框
- 当前步骤：高对比蓝色焦点框
- 背景与正文维持 WCAG AA 对比度

卡片圆角不超过 6px。方法名、签名和源码证据使用等宽字体；解释和参数含义使用易读的无衬线字体。正文不少于 13px、行高不少于 1.55，长中文和长符号允许自然换行。

## 7. 窄屏与可访问性

双轨图需要稳定宽度来保持方向关系。窄屏不把两轨挤成无法阅读的细列，而是在图容器上允许水平滚动；头部、覆盖说明和遗漏清单自适应为单列。

- 所有按钮有 `aria-label` 和 title。
- Tab 使用 `role=tablist/tab` 与 `aria-selected`。
- 节点是可聚焦按钮，展开状态使用 `aria-expanded`。
- `:focus-visible` 有清晰描边。
- 遵循 `prefers-reduced-motion`。

## 8. 禁止事项

- 不把抽样链路描述为全量项目流程。
- 不从节点顺序推断边，也不在断链后画下游。
- 不省略返回轨或只画一根“返回”总箭头。
- 不用模糊的“参数对象”代替方法形参和调用实参。
- 不只写 ORM 类名而不展示真实表和操作。
- 不让连线穿过卡片或让标注覆盖正文。
- 不用外部 CDN；成品必须作为单文件离线打开。
- 不添加渐变装饰、浮动图形或与调用链无关的说明性营销文案。
