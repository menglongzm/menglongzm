# code-flow-visual Skill 修订记录

> 关联原始需求：根据用户要求，对功能点、模块或整个项目进行可视化解释；从前端请求地址追到 Controller、Service、数据访问与具体数据库，展示每个节点的主要功能、方法和参数，并把数据返回路径追到最终结果。

## 一、第一轮：断链与代码根边界

第一轮建立以下原则：

- 只追踪静态代码能够确认的流程。
- 跨仓、运行时拦截、动态分发、反射和不可读 MQ 消费者等位置使用断链节点。
- 断链记录已知 URL/方法/参数、`breakReason` 和 `knownNext`，其后不臆造节点。
- 在当前目录、父目录和兄弟目录尽力探测前后端代码根。
- 静态可读的前后端拦截器、中间件和消费者继续追踪，不误判为断链。

该轮修改了 `SKILL.md`、`references/call-chain-analysis.md`、`references/visualization-design.md` 和旧 HTML 骨架中的文字约束。

## 二、第二轮：排版与连线规范

第二轮针对中文可读性、节点展开后箭头错位和连线标注覆盖正文，增加：

- 正文字号、行高、换行和参数表宽度底线。
- 请求/返回双轨与层间走线规则。
- edge label 背景和位置约束。
- `ResizeObserver` 重算连线的要求。

### 状态更正

旧记录曾把空的 `drawConnectors()` 和注释性 `ResizeObserver` 骨架标记为“已解决”。审查后确认它们只是生成提示，并没有可执行的节点渲染、连线、播放或碰撞处理，因此不能视为已实现。第三轮已用真实模板替换该骨架。

## 三、第三轮：从说明性 skill 到可执行工作流

### 1. 统一数据合约

新增 `references/flow-data-schema.md`，使用 `FLOW_DATA` 统一描述：

- `feature / module / project` 范围与 `complete / sampled / partial` 覆盖状态
- 入口盘点、追踪数量、选择依据和遗漏入口
- 多 flow、请求/返回/分支节点和显式边
- Controller、Service、DAO 方法签名和形参
- 调用点实参到目标形参的映射
- 数据库系统、表、SQL 操作与关键条件
- 返回结构的 `before / after / action`
- 最终 HTTP 响应和结构化断链
- 节点与边的源码路径、行号和证据类型

### 2. 可执行校验与生成

新增：

- `scripts/validate-flow-data.mjs`
- `scripts/render-flow.mjs`
- `assets/flow-template.html`

校验器会拒绝：重复/未知 ID、不可达节点、缺少签名或参数的方法节点、缺少实参映射的调用边、缺少表信息的数据库节点、缺少转换信息的返回边、没有最终响应的完整链、断链后继续连线、只有运行时猜测证据的普通节点/边，以及不一致的抽样统计。

生成器只接受校验通过的数据，并安全注入固定单文件模板。模板已实现 flow Tab、覆盖披露、双轨泳道、节点详情、SVG 连线、播放控制、轨道开关、主题切换、窄屏降级和浏览器诊断。

### 3. 分档覆盖规则

- `feature`：完整追踪用户指定入口；不可分析处标 `partial/broken`。
- `module`：先盘点所有入口，再选 2-5 条；不是全量时必须显示 `sampled`、比例和遗漏清单。
- `project`：先盘点模块和入口，再选 1-3 条代表链；不能把抽样结果称为全项目完整链路。

### 4. 可执行评测

新增 `evals/evals.json` 及 fixtures：

- `complete-order-flow.json`：前端 -> Controller -> 两个 Service -> Repository -> 两张表 -> 实体/聚合 -> DTO -> 包装 -> HTTP JSON。
- `sampled-order-module.json`：发现 9 个入口，追踪 3 个，列出 6 个遗漏入口。
- `broken-backend-flow.json`：后端不可读，在网关边界诚实断链。
- `invalid-break-continuation.json`：断链后臆造 Controller 的反例，必须被校验器拒绝。

## 四、七项原始需求映射

| 原始子需求 | 当前落地 |
|---|---|
| 功能点 / 模块 / 项目三档 | `SKILL.md` 范围流程 + schema 覆盖统计 + HTML flow Tab |
| 从前端请求地址开始 | frontend node 的 `http.method/url/params` + 入口可达性校验 |
| 展示到最终返回结果 | complete flow 强制 `responseNodeId` 和 response 节点 |
| 每个节点与主要功能 | node 的 `layer/symbol/role/result/evidence` |
| Controller 方法及参数 | `signature/params` 强制规则 + 调用边形参与实参匹配 |
| Service 到具体数据库 | Service-to-Service、data-access、database 元数据与真实终点规则 |
| 展示具体返回路径 | 独立 return edges，逐跳强制 `before/after/action` |

断链原则仍是上述需求在代码不可达时的诚实边界，不替代任何可读层，也不允许用“断链”掩盖未完成的源码搜索。

## 五、第四轮：浏览器验收与 Bug 修复

### 1. TDZ Bug 修复

`let drawFrame = 0;` 原先声明在 `renderFlow()` 调用之后。由于 `renderFlow()` 内部调用 `scheduleDraw()`，而 `scheduleDraw()` 引用 `drawFrame`，在 `drawFrame` 声明前访问会触发 TDZ (Temporal Dead Zone) ReferenceError。这导致 `observeMap`、事件绑定和 `window.__flowData` 赋值全部未执行。

修复：将 `let drawFrame = 0;` 移至 IIFE 开头 `const state` 声明之后。

### 2. 同步初始渲染后备

`drawConnectors()` 原先仅通过 `requestAnimationFrame` 调度。当页面不可见（后台标签页、无头浏览器）时，浏览器暂停 rAF 回调，导致 SVG 连线不渲染。

修复：在 `renderFlow()` 末尾的 `observeMap(map)` 之后添加直接 `drawConnectors()` 调用，确保连线在初始渲染时同步绘制。后续的 rAF 和 ResizeObserver 回调负责处理节点展开、Tab 切换和视口改变时的重绘。

### 3. 验收结果

- 三组正例 fixtures 通过 validator。
- 非法断链 fixture 以 3 个错误按预期失败。
- 三个页面在浏览器中正确加载，控制台无错误。
- 完整链：13 节点、13 边、双轨泳道、节点展开、播放步进、重置、轨道开关、主题切换全部正常。
- 抽样页：module/sampled/3/9 徽章、3 个 Tab、6 个遗漏入口、每条链 broken 且断链零出度。
- 断链页：动态 URL、range/format 参数、断链原因与 knownNext、无臆造下游、断链零出度。
- fullPage 截图重复问题未复现，确认为 IAB 截图拼接限制。
- 窄屏 CSS 媒体查询规则存在，YoBrowser 无法改变视口尺寸做实际窄屏测试。

## 六、第五轮：Schema v2 与可审计性增强

### 1. 强化唯一数据合约

`flow-data-schema.md` 升级为 version 2，新增：

- `paths`：每条路径含条件、有序 steps（nodeId + edgeId）、terminalNodeId 和 dbOperationCount。播放不再从全图边排序猜测，严格使用当前 path steps。
- `transactions`：事务入口、成员、事务外操作、提交点和回滚条件。
- `result.source`：`query-result | affected-row-count | in-memory-object | generated-value | response-body | unknown`，记录 `consumed` 形成数据流可追溯链。
- `result.consumed`：记录结果被哪个节点/边消费。
- `database.returnsRows` + `returnsRowsEvidence`：DML 默认只产生 `affected-row-count`；声称返回行需 RETURNING/二次查询证据。
- `spawn` 边类型：异步派生请求使用独立 spawn path，不能出现在父路径同步返回序列中。
- `http.urlMapping`：区分 browserPath、axiosBaseURL、proxyRewrite、upstreamPath、controllerRoute。
- 扩展证据 basis：增加 `framework-derived` 和 `config-scoped`。
- `http.params[].in`：必须为 `path | query | header | body`。
- 独立操作实例原则：同一 Mapper 方法执行多次用不同节点 ID；禁止合并多 DAO/DB 操作。

### 2. 修复并增强 Validator

`validate-flow-data.mjs` 修复和新增：

- 修复 `http.params` 非数组时 `.map()` 崩溃：改为 `validateHttpParams()` 独立处理，所有坏输入返回结构化错误。
- 校验 `http.params[].in` 字段。
- 校验 `paths` 连续性：每步 edgeId 必须从上一步 nodeId 出发到达本步 nodeId。
- 校验所有节点和边至少属于一条 path。
- 校验 `dbOperationCount` 等于 path steps 中数据库节点数。
- 校验 DML `result.source` 为 `query-result` 时必须有 `returnsRows` 证据。
- 校验 `spawn` 边不出现在父路径同步序列中。
- 校验 `transactions` 成员不与事务外操作重叠。
- 校验 `commitPointNodeId` 必须为 return lane 节点。
- 校验扩展证据 basis。

### 3. 增强生成模板

`flow-template.html` 新增：

- 路径选择控件：当 `flow.paths` 存在时显示 radio 选择器，播放严格使用当前 `path.steps`。
- Tab `aria-controls`/`tabpanel` 关联：flow-shell 设置 `role="tabpanel"` 和 `aria-labelledby`。
- `spawn` 边样式：使用 `--focus` 色点线和 `arrow-spawn` marker。
- 扩展 `__flowDiagnostics()`：新增 `linesCrossingCards`、`labelsOverlappingCards` 和 `pathIssues` 检查。
- 字号提升：`.kind`、`.layer-label`、`.detail-section h3`、`.edge-note code` 从 11px 提升到 12px。

### 4. 新增 HTML 校验器

`scripts/validate-rendered-html.mjs` 检查：

- doctype、lang、viewport、唯一 `#flow-data`、占位符已替换、无外部依赖、无重复静态 ID。
- 提取嵌入 JSON 再次运行 `validateFlowData`。
- 检查必要控件、ARIA tablist/tabpanel、诊断接口、ResizeObserver。
- 检查安全注入（无裸 `</script>`）。
- `render-flow.mjs` 生成后自动调用 HTML 校验，失败时不报告成功。

### 5. 新增单元测试

`tests/` 目录新增：

- `tests/validate-flow-data.test.mjs`：正例 fixture 通过、反例 fixture 失败、崩溃保护（非数组/null params）、schema v2 特性（version 1 拒绝、missing paths 失败、DML returnsRows 校验、扩展证据接受、params.in 校验、path 不连续失败、事务重叠失败）。
- `tests/render-flow.test.mjs`：有效数据渲染为合法 HTML、无效数据被拒绝、`</script>` 注入安全转义。
- `tests/validate-rendered-html.test.mjs`：缺 doctype/lang/viewport/placeholder/外部依赖/诊断接口/ResizeObserver/控件均失败。
- `tests/fixtures/complete-order-flow-v2.json`：含 paths、transactions、result.source 语义的完整正例。
- `tests/fixtures/invalid-break-continuation-v2.json`：断链后臆造下游的反例。
